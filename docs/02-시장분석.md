# 줍줍!(Joop Joop!) 시장분석

> 웹 원터치 아케이드 게임 "줍줍!"의 시장 환경, 레퍼런스 게임, 포지셔닝을 정리한 문서.
> 작성일: 2026-08-10

---

## 1. 시장 개요

### 1.1 하이퍼캐주얼 게임 시장

- 하이퍼캐주얼은 "설명 없이 3초 안에 이해되는 조작 + 짧은 세션 + 즉시 재도전"을 핵심으로 하는 장르다. 2017~2021년 Voodoo, Ketchapp 등 퍼블리셔 주도로 모바일 다운로드 차트를 지배했다.
- 2022년 이후 광고 단가 상승과 애플 ATT(추적 제한)로 순수 하이퍼캐주얼의 수익 모델이 약화되면서, 시장은 **하이브리드 캐주얼**(하이퍼캐주얼 조작 + 수집/성장/메타 요소)로 이동했다. 줍줍!의 "스킨 수집 + 화폐" 구조는 이 흐름과 일치한다.
- 장르 자체의 수요는 여전히 크다. 조작이 단순한 게임은 언어·연령·게임 경험의 장벽이 낮아 잠재 이용자 폭이 가장 넓다.

### 1.2 웹(브라우저) 게임 시장

- Poki, CrazyGames 등 웹 게임 포털의 트래픽이 꾸준히 성장 중이며, 월간 수천만 명 규모의 이용자가 브라우저에서 직접 게임을 즐긴다. Wordle(2022)의 성공은 "URL 하나로 퍼지는 게임"의 바이럴 잠재력을 보여준 대표 사례다.
- 모바일 브라우저 성능(WebGL/WebGPU, Canvas)이 충분히 올라와, 2D 아케이드 수준의 게임은 네이티브 앱과 체감 차이가 거의 없다.
- 웹 게임의 강점: 설치 장벽 제로, 링크 공유만으로 전파, 스토어 심사·수수료 없음, 즉시 업데이트.
- 웹 게임의 약점: 푸시 알림·홈 화면 아이콘 등 리텐션 장치가 약하고, 스토어 차트 노출 같은 자연 유입 채널이 없다. 유통은 전적으로 링크 공유와 포털 입점에 의존한다.

### 1.3 요약

| 항목 | 시사점 |
|---|---|
| 하이퍼캐주얼 → 하이브리드화 | 수집·메타 요소(스킨, 화폐)는 선택이 아니라 기본기 |
| 웹 포털 트래픽 성장 | Poki/CrazyGames 입점이 현실적인 유통 경로 |
| Wordle식 바이럴 | "점수 자랑 + URL 공유" 루프 설계가 유효 |
| 리텐션 장치 부재 | 웹의 약점을 데일리 요소·수집 목표로 보완 필요 |

## 2. 레퍼런스 게임 분석

원터치 조작, 특히 "탭으로 상태를 전환"하는 계열의 대표작을 분석한다.

| 게임 | 조작 | 핵심 루프 | 성공 요인 |
|---|---|---|---|
| **Flappy Bird** (2013) | 탭 = 점프 | 장애물 통과, 즉사, 즉시 재시작 | 극단적 단순함 + 절묘한 난이도 + 점수 자랑 바이럴 |
| **Orbit / Orbia 계열** | 탭 = 궤도 이탈·전환 | 궤도를 옮겨가며 전진 | "궤도 전환" 조작의 리듬감, 타이밍 긴장감 |
| **Circle Rush / Duet** | 탭·홀드 = 회전 전환 | 회전체로 장애물 회피 | 회전 패턴의 예측 가능성, 실패가 항상 "내 탓"으로 느껴짐 |
| **Timberman** (2014) | 좌우 탭 | 나무 찍기 + 가지 회피, 시간 압박 | 콤보 속도감 + 캐릭터 스킨 수집이 리텐션 견인 |
| **Crossy Road** (2014) | 탭·스와이프 | 전진 + 수집 화폐로 캐릭터 뽑기 | 하이퍼캐주얼에 캐릭터 수집을 결합한 원형. 스킨이 공유 욕구를 자극 |

### 레퍼런스에서 확인되는 공통점

1. **조작 설명이 필요 없다** — 첫 화면에서 탭 한 번이면 규칙을 몸으로 이해한다.
2. **죽음 → 재시작이 3초 이내** — 실패의 비용이 낮아 "한 판만 더"가 자연스럽다.
3. **실패가 납득된다** — 랜덤 억울함이 아니라 내 타이밍 실수로 죽는다.
4. **점수가 자랑거리다** — 한 줄 점수가 공유·경쟁의 단위가 된다.
5. **수집이 장기 목표를 만든다** — Timberman·Crossy Road는 스킨 수집으로 단기 루프의 수명을 연장했다.

## 3. 성공 요인 도출

레퍼런스 분석에서 줍줍!이 반드시 갖춰야 할 요소를 정리한다.

| 성공 요인 | 정의 | 줍줍!에서의 구현 |
|---|---|---|
| 즉시 이해되는 조작 | 튜토리얼 없이 규칙 체득 | 탭 = 두 궤도 링 사이 전환, 단 하나의 입력 |
| 3초 안에 재도전 | 실패 → 재시작 마찰 최소화 | 게임오버 화면에서 탭 한 번으로 즉시 재시작 |
| 짧은 세션 | 1판 30초~2분 | 점진적 속도 상승으로 자연스러운 판 길이 형성 |
| "one more try" 루프 | 아쉬운 실패가 재도전 유발 | 최고 점수 근접 표시, 아깝게 놓친 파편 연출 |
| 수집욕·캐릭터 애착 | 장기 목표와 정서적 연결 | 주운 쓰레기 = 화폐 → '줍' 스킨 해금 |
| 콤보·피버 | 숙련자의 상한 확장 | 연속 수집 콤보 → 피버 모드로 점수 배율 |

핵심은 **단기 루프(탭-회피-수집)와 장기 루프(화폐-스킨)의 연결**이다. 순수 하이퍼캐주얼은 3일이면 소진되지만, 수집 목표가 있으면 "오늘은 다음 스킨까지"라는 복귀 이유가 생긴다.

## 4. 줍줍!의 포지셔닝과 차별화

### 4.1 포지셔닝

> **"세계관과 캐릭터가 있는 원터치 웹 아케이드"**
> — 조작은 Flappy Bird만큼 단순하게, 애착은 Crossy Road만큼 깊게, 배포는 Wordle만큼 가볍게.

### 4.2 차별화 요소

| 요소 | 일반적인 하이퍼캐주얼 | 줍줍! |
|---|---|---|
| 세계관 | 없음(추상 도형) | 케슬러 신드롬 — 우주 쓰레기 청소라는 실재하는 문제 |
| 플레이의 의미 | 점수 | "궤도를 청소한다"는 친환경 내러티브. 수집 행위 자체가 테마와 일치 |
| 캐릭터 | 없거나 도구적 | 반려 로봇 '줍' — 귀여움 기반 애착, 스킨 수집의 감정적 동기 |
| 아트 | 미니멀 플랫 | 카세트퓨처리즘(CRT/네온) — 스크린샷만으로 식별되는 고유 룩 |
| 배포 | 앱스토어 | 웹 URL — 설치 없음, 링크 공유 즉시 플레이, Vercel로 즉시 업데이트 |

### 4.3 차별화가 작동하는 이유

- **테마와 메커니즘의 일치**: "쓰레기를 줍는다"가 곧 점수·화폐 획득이다. 세계관이 장식이 아니라 핵심 루프 그 자체라서 설명 비용이 없다.
- **귀여운 캐릭터 + 수집**: 하이퍼캐주얼의 최대 약점(정서적 연결 부재)을 보완한다. 스킨은 곧 공유용 스크린샷 소재가 된다.
- **웹 배포**: "이거 해봐" + URL 한 줄이면 전파가 끝난다. 게임 길이(30초~2분)와 접근 비용(0초 설치)이 정확히 맞물린다.
- **고유 아트 스타일**: 하이퍼캐주얼 시장은 비주얼이 상향 평준화·동질화되어 있어, CRT/네온 룩은 그 자체로 마케팅 자산이다.

## 5. 리스크와 대응

| 리스크 | 내용 | 대응 |
|---|---|---|
| 리텐션 장치 부재 | 웹은 푸시 알림·앱 아이콘이 없어 복귀 유도가 어려움 | 스킨 수집 목표, 일일 보너스, PWA(홈 화면 추가) 안내, 최고 기록 갱신 알림 UI |
| 발견성(디스커버리) | 스토어 차트가 없어 자연 유입이 없음 | 점수 공유 이미지/URL 자동 생성, Poki·CrazyGames 등 포털 입점 검토, SNS용 플레이 클립 |
| 콘텐츠 소진 | 단일 메커니즘은 수명이 짧음 | 스킨 외 배경 테마·장애물 패턴 단계적 추가, 콤보/피버로 숙련 상한 확보 |
| 모바일 웹 성능 편차 | 저사양 기기·브라우저별 프레임 저하 | Canvas 2D 기반 경량 렌더링, 파티클 수 조절 옵션, 60fps 목표의 성능 예산 관리 |
| 조작 오인식 | 브라우저 기본 제스처(스크롤·더블탭 줌)와 충돌 | `touch-action` 제어, 전체 화면 탭 영역, 첫 판에서 조작 확인 |
| 유사작 다수 | 궤도 전환류는 이미 많음 | 세계관·캐릭터·아트로 식별성 확보(4장). 메커니즘이 아닌 "줍"으로 기억되게 함 |
| 수익화 한계 | 웹 광고 단가는 앱 대비 낮음 | 초기에는 수익화보다 트래픽·리텐션 검증에 집중. 포트폴리오/커뮤니티 가치 우선 |

## 6. 결론

- 시장은 "순수 하이퍼캐주얼"에서 "수집·메타가 있는 하이브리드 캐주얼"로 이동했고, 줍줍!의 스킨 수집 구조는 이 방향과 맞는다.
- 원터치 명작들의 공통 공식(즉시 이해, 3초 재도전, 납득되는 실패, 점수 자랑, 수집)을 기본기로 충실히 구현하는 것이 최우선이다.
- 차별화의 축은 메커니즘이 아니라 **세계관(우주 청소) × 캐릭터(줍) × 아트(카세트퓨처리즘) × 배포(웹 URL)**의 조합이다.
- 웹 배포의 약점(리텐션·발견성)은 알려진 문제이며, 수집 목표와 공유 루프 설계로 보완한다.
